# Chạy BE laptop với MySQL EC2

Đã chuyển sang DB EC2 hiện có, giữ dữ liệu AWS thay vì đè snapshot Aiven. Aiven vẫn được giữ để có thể quay lại. File `mar-ec2-key.pem` dùng đăng nhập SSH; không phải CA MySQL. CA MySQL được lấy từ máy chủ đã ghim SSH host key, đưa vào truststore PKCS12 để JDBC kiểm tra CA.

## Đường kết nối

```text
Pi --HTTPS LAN/MQTT--> BE laptop
                          |
                      JDBC + TLS VERIFY_CA
                          |
                  aws-db-tunnel:3306 (Docker nội bộ)
                          |
                  SSH có ghim host key --> EC2:22
                                             |
                                      127.0.0.1:3306
                                      mediassistrover
```

Tunnel không publish cổng 3306 ra laptop/LAN. MySQL EC2 vẫn bind loopback; không cần mở 3306 trong Security Group. Container tunnel tự khởi động lại cùng Docker, SSH keepalive 10 giây × 3; đóng tunnel thì JDBC mất kết nối và phải phục hồi, không chuyển ngầm sang DB khác. Khi đổi mạng, Security Group SSH phải cho phép IP nguồn mới của laptop.

`VERIFY_CA` xác minh CA MySQL bên trong đường SSH đã xác minh host key. Chứng chỉ MySQL tự tạo không mang DNS `aws-db-tunnel`, nên không dùng VERIFY_IDENTITY với tên dịch vụ Docker này. Không tắt TLS hoặc SSH host-key checking.

## Những gì được giữ và nâng cấp

- Schema AWS V38 đã được Flyway kiểm tra checksum và nâng lên V39; Hibernate validate thành công. V39 tạo MapBinaryAsset, không thay ID robot/map/endpoint/zone.
- Robot: `0e3f1083-2546-4f45-8004-5eda5cb75a6f`, code `mar-v1`. Secret trên Pi xác thực được với AWS; không tạo Robot ID hay secret mới.
- Map cũ AWS: `c342d669-cfbe-447a-a36d-f28b542f61e7`, hash `fb24fa05ce645185e80ff6f1e579ca016039bd409e6340dd973ce53015bea833`.
- YAML 170 byte và PGM 23.726 byte đã chép vào MapBinaryAsset; SHA-256 trong DB khớp payload. PNG được sinh từ map trong DB; Pi tải được ZIP qua HTTPS.
- Ba endpoint a/b/c và zone cũ được giữ nguyên. Map mới quét hôm nay trên Aiven không được nhập sang AWS trong lần chuyển này.
- Map quét mới được upload từ Pi qua BE; receipt, gói map và catalog dùng DB AWS theo `app.mapping.storage-backend=DATABASE`. Không cần Pi nối trực tiếp MySQL.
- Backup trước nâng cấp nằm trong `secrets/aws/mediassistrover-before-*.sql`, có bản đối chiếu SHA-256 và bản trên EC2 `/home/ubuntu/mar-db-backups`. Không commit backup/credentials vào Git.

## Chạy lại BE

Chạy PowerShell tại bản triển khai hiện tại:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
Set-Location 'C:\Users\LENOVO\Downloads\MAR_EMQX_Demo\BE_MAR'
.\deploy\Use-MarAwsDb.ps1 -EnableDispatch
```

Trước khi đổi DB/restart, kết thúc job và dừng stack Pi. Script kiểm tra source/target không có job giữ robot, kiểm tra TLS/identity/schema rồi khởi động đúng một BE. `Use-MarAwsDb.ps1` không có `-EnableDispatch` là chế độ inspection: MQTT, dispatch, scheduler tắt. Chỉ dùng `-EnableDispatch` sau khi có receipt xác minh DEVICE và map storage.

Tệp riêng tại máy triển khai: `.env.aws`, `secrets/aws/ec2-key.pem`, `known_hosts`, `ca.pem`, `truststore.p12`, `backup-receipt.json`, `inspection-receipt.json`. `.env.aws` và toàn bộ secrets bị Git ignore. Không nhúng chúng vào image. `secrets/database-provider.txt` chứa `aws`; NetworkCompose.ps1 đọc lựa chọn này, nên chạy lại script đổi IP/HTTPS sẽ giữ AWS thay vì tự quay lại Aiven.

## Quét mới hoặc dùng map cũ

BE ở nhà: `192.168.1.63`; Pi: `192.168.1.65`. Đây là địa chỉ runtime đã xác minh lúc chuyển DB, không phải địa chỉ cố định trong code.

```powershell
ssh pi@192.168.1.65
```

HOST Pi:

```sh
sudo docker exec -it -u ubuntu -w /home/ubuntu/mediassist-mqtt-2026-10-08 MentorPi zsh
```

Trong container, quét map mới:

```sh
cd /home/ubuntu/mediassist-mqtt-2026-10-08
zsh tools/robot.zsh run
```

Mở `http://127.0.0.1:8080/mapping.html`, đăng nhập token ADMIN mới, chuẩn bị workflow quét và tạo job. Robot ID như trên; Floor ID AWS `c214abc7-c887-11f1-904a-f63b6c16c38d`; workflow quét đã publish `74ecb162-b119-3546-2ac6-a28109fe7518`. Khi lưu, map mới có ID mới trên AWS. Không dùng lại Job/Request/Map ID chỉ tồn tại trong Aiven.

Dùng map cũ: tải map AWS ID ở trên, mở phiên map mới trên UI, rồi chạy `zsh tools/navigation_session.zsh` sau khi đã dừng chế độ quét. Xác nhận vị trí thực trên bản đồ trước MOVE. Không tự phát lệnh bánh trong lần chuyển DB này.

## Quay lại Aiven khi cần

Sau khi dừng Pi và đóng hết job/phiên AWS:

```powershell
.\deploy\Use-MarCloudDb.ps1 -EnableDispatch
```

Đây là quay lại DB Aiven đã giữ nguyên, không đồng bộ tự động các map/job mới phát sinh ở AWS. Helper cập nhật provider marker về `aiven` sau khi BE lên. Chỉ để một BE bật MQTT/dispatch quản lý cùng robot; BE khác dùng để xem dữ liệu phải tắt MQTT/dispatch/scheduler.
